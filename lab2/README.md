# Лабораторна робота №2: Віртуалізація списків та побудова навігації

**Тема:** Віртуалізація списків та побудова навігації.

## Опис проєкту

Мобільний застосунок на React Native (Expo) із захищеною бічною навігацією (Drawer), глобальним станом авторизації та оптимізованими списками. Застосунок складається з таких частин:

| Екран | Файл | Опис |
|-------|------|------|
| Вхід (публічний) | `src/app/login.jsx` | Форма авторизації (логін і пароль). Після успішного входу користувача автоматично перенаправляє в застосунок |
| Стрічка новин | `src/app/(drawer)/(news)/index.jsx` | `FlatList` зі 120 новин, Pull-to-Refresh, Infinite Scroll, оптимізації `getItemLayout` та `React.memo` |
| Деталі новини | `src/app/(drawer)/(news)/[id].jsx` | Динамічний маршрут, параметр `id` отримується через `useLocalSearchParams` |
| Довідковий центр | `src/app/(drawer)/faq.jsx` | Згруповані запитання та відповіді, відображені через `SectionList` |

Тестові дані для входу: **логін `admin`, пароль `1234`**.

### Реалізовані архітектурні рішення

- **Глобальний стан авторизації.** `src/context/AuthContext.jsx` містить контекст зі станом `isAuthenticated` та функціями `login()` і `logout()`. Кореневий `src/app/_layout.jsx` обгорнуто в `AuthProvider`.
- **Публічний екран входу.** Якщо користувач уже авторизований, `login.jsx` виконує `<Redirect href="/" />`, тому після виклику `login()` перехід відбувається автоматично.
- **Захищена Drawer-навігація.** У `src/app/(drawer)/_layout.jsx` виконується перевірка: для неавторизованого користувача повертається `<Redirect href="/login" />`, для авторизованого рендериться `<Drawer>` із кнопкою «Вийти», що викликає `logout()`.
- **Вкладений Stack.** Підгрупа `src/app/(drawer)/(news)` містить власний `Stack` із `headerShown: false`, щоб заголовок стека не дублював заголовок Drawer.
- **Безпечні зони.** Відступи від вирізів екрана, статус-бару та системних панелей реалізовано через `react-native-safe-area-context` (`SafeAreaView`, `useSafeAreaInsets`).

### Оптимізація списку новин

- `getItemLayout` розраховує позицію елементів за фіксованою висотою картки без додаткового вимірювання розмітки.
- Картка `NewsCard` обгорнута в `React.memo`, тому вже відображені елементи не перерендерюються під час оновлення стану батьківського компонента.
- Додатково задано `keyExtractor`, `initialNumToRender`, `maxToRenderPerBatch`, `windowSize` та `removeClippedSubviews`.
- `renderItem` та обробники обгорнуті в `useCallback`, щоб посилання на функції не змінювалися між рендерами.
- Pull-to-Refresh: властивості `refreshing` та `onRefresh`. Infinite Scroll: `onEndReached` та `onEndReachedThreshold={0.5}`, нові дані підвантажуються порціями по 20 елементів до 120.

### Використані технології

- **Expo** та **Expo Router** (файлова маршрутизація, групи маршрутів, динамічні маршрути)
- **Drawer** з `expo-router/drawer`, `react-native-gesture-handler`, `react-native-reanimated`, `react-native-worklets`
- **React Native**: `FlatList`, `SectionList`, `ScrollView`, `Pressable`, `TextInput`, `Image`
- **React Context API**, хуки `useState`, `useCallback`, `useMemo`, `useRef`
- **@expo/vector-icons**, **react-native-safe-area-context**
- **StyleSheet API** та Flexbox

## Відповіді на контрольні запитання

### 1. Як працює вкладена навігація в архітектурі Expo Router?

У Expo Router структура навігації визначається структурою файлів і папок у каталозі `app`. Кожна папка може містити файл `_layout`, який описує навігатор (`Stack`, `Tabs`, `Drawer`) для всіх маршрутів цієї папки. Layout-файли вкладаються один в інший, і так утворюється ієрархія навігаторів: екрани рендеряться всередині навігатора свого layout, а той, своєю чергою, є екраном навігатора вищого рівня.

У проєкті ця ієрархія виглядає так: кореневий `Stack` (`app/_layout.jsx`) містить екран `login` та групу `(drawer)`, яка є `Drawer`, а в ній розташована група `(news)` зі своїм `Stack`, що містить `index` та `[id]`. Назви папок у круглих дужках (групи маршрутів) використовуються лише для організації та не потрапляють в URL: екран `app/(drawer)/(news)/index.jsx` доступний за адресою `/`. Щоб заголовок вкладеного стека не дублював заголовок Drawer, у вкладеному навігаторі встановлюється `headerShown: false`.

### 2. Яким чином реалізується захист маршрутів від неавторизованого доступу?

Стан авторизації зберігається в глобальному контексті (`AuthContext`) з прапорцем `isAuthenticated`. У layout-файлі захищеної групи `app/(drawer)/_layout.jsx` перевіряється цей прапорець: якщо користувач не авторизований, компонент повертає `<Redirect href="/login" />`, тому жоден екран групи не відображається. Для авторизованого користувача повертається `<Drawer>`.

Оскільки перевірка виконується в layout групи, вона захищає одразу всі вкладені маршрути. Зміна стану працює і в зворотний бік: після виклику `logout()` значення `isAuthenticated` стає `false`, layout перерендерюється і автоматично виконує перенаправлення на екран входу. Екран `login.jsx`, навпаки, перенаправляє вже авторизованого користувача на головний екран застосунку.

### 3. Чим FlatList відрізняється від ScrollView та що таке віртуалізація списків?

`ScrollView` рендерить усі дочірні елементи одразу, навіть ті, що не видно на екрані. Для невеликого набору контенту це зручно, але для сотень елементів призводить до високого споживання пам'яті та повільного першого відображення.

`FlatList` використовує **віртуалізацію**: створюються лише елементи, що потрапляють у видиму область (плюс невеликий буфер навколо неї), а елементи, які пішли далеко за межі екрана, вивільняються з пам'яті й замінюються порожніми заповнювачами. Так кількість змонтованих компонентів залишається майже постійною незалежно від розміру даних. Робота списку налаштовується параметрами `initialNumToRender`, `maxToRenderPerBatch`, `windowSize`, `removeClippedSubviews`. Додатково `getItemLayout` дозволяє обчислювати позиції без вимірювання, а `React.memo` та `keyExtractor` зменшують кількість зайвих перерендерів. `FlatList` також надає готові механізми Pull-to-Refresh (`onRefresh`) та Infinite Scroll (`onEndReached`).

### 4. Як отримати параметри динамічного маршруту на цільовому екрані в Expo Router?

Динамічний сегмент позначається квадратними дужками в назві файлу, наприклад `[id].jsx`. На цільовому екрані параметри отримуються хуком `useLocalSearchParams`:

```jsx
import { useLocalSearchParams } from "expo-router";

const { id } = useLocalSearchParams();
```

Значення передається під час навігації, наприклад `router.push("/5")` або `router.push({ pathname: "/[id]", params: { id: "5" } })`. Хук повертає параметри саме поточного екрана (на відміну від `useGlobalSearchParams`, який повертає параметри глобально активного маршруту). Значення параметрів мають рядковий тип, тому за потреби їх потрібно перетворювати, як у проєкті: `Number(id)`.

### 5. Яку структуру даних приймає компонент SectionList?

Властивість `sections` приймає масив об'єктів-секцій. Кожна секція містить масив елементів у полі `data` та, за потреби, додаткові поля (наприклад, `title`):

```js
const sections = [
  { title: "Навчання", data: [{ id: "s1", q: "...", a: "..." }] },
  { title: "Застосунок", data: [{ id: "a1", q: "...", a: "..." }] },
];
```

Для відображення використовуються `renderItem` (рендер елемента секції), `renderSectionHeader` (заголовок секції, отримує об'єкт `section`) та `keyExtractor` (унікальний ключ елемента). За допомогою `stickySectionHeadersEnabled` заголовки секцій можна «приклеювати» до верху екрана під час прокрутки. Як і `FlatList`, `SectionList` є віртуалізованим списком.

## Висновки

У ході лабораторної роботи було створено застосунок на Expo Router із захищеною бічною навігацією. Реалізовано глобальний стан авторизації через React Context, публічний екран входу та перевірку доступу в layout групи маршрутів із перенаправленням через `<Redirect>`. Опановано вкладені навігатори: кореневий `Stack`, `Drawer` та вкладений `Stack` для новин, а також групи маршрутів, які впливають на структуру навігації, але не на URL.

Для відображення великих обсягів даних використано віртуалізовані списки. Стрічка новин на `FlatList` зі 120 елементами підтримує оновлення жестом та підвантаження під час прокрутки, а також оптимізована за допомогою `getItemLayout`, `React.memo`, `useCallback` та параметрів вікна рендерингу. Для згрупованих даних застосовано `SectionList`. Динамічний маршрут `[id]` дозволив передавати параметр на екран деталей і отримувати його через `useLocalSearchParams`.

Під час виконання роботи також виявлено, що в нових версіях Expo SDK Drawer входить до складу `expo-router`, тому окремий пакет `@react-navigation/drawer` може конфліктувати з роутером. Для вмісту бічного меню було використано власний компонент на базі стандартних компонентів React Native. Відступи від системних елементів інтерфейсу реалізовано через `react-native-safe-area-context`.
